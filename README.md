# NEO-SCOPE

## Near-Earth Object Space Intelligence Platform

NEO-SCOPE is a data-driven web platform for exploring Near-Earth Objects
(NEOs) using real observations from NASA's Near Earth Object Web Service
(NeoWs), interactive orbital visualizations, scientific measurements,
and an educational machine-learning risk analysis layer.

The project turns raw astronomical observations into an interactive
scientific experience while keeping the distinction between NASA-derived
data, project-derived features, and machine-learning predictions
visible.

> **Important:** NEO-SCOPE is an independent educational/research
> project. Its machine-learning outputs are derived predictions and are
> not official NASA impact probabilities or collision forecasts.

------------------------------------------------------------------------

## What NEO-SCOPE Does

-   Explore Near-Earth Objects using NASA NeoWs data
-   Visualize orbital and close-approach information
-   Analyze velocity, miss distance, size, and absolute magnitude
-   Apply machine-learning-based risk classification
-   Explain which features influenced a model prediction
-   Compare NEO sizes with humans, buildings, aircraft, the Moon, and
    Earth
-   Provide source and methodology links alongside the data
-   Refresh observations from NASA's API

## Core Experience

### What's Passing By?

An immersive orbital visualization showing selected NEOs in relation to
Earth, with object details such as close-approach date, velocity, miss
distance, estimated diameter, and risk-related status.

The visualization does not imply an impact trajectory unless the
underlying source explicitly supports that interpretation.

### Read the Trajectory

Interactive scientific visualizations explore relationships such as:

-   Relative velocity vs. miss distance
-   Diameter vs. miss distance
-   Absolute magnitude vs. estimated size
-   Other derived feature relationships

### Risk Lab

The machine-learning layer uses selected NEO characteristics to produce
a project-generated classification or risk score.

Possible inputs include:

-   Relative velocity
-   Miss distance
-   Absolute magnitude
-   Estimated diameter
-   Other available derived features

These outputs are explicitly separated from authoritative NASA/JPL
classifications.

### Why This Object?

Model explainability helps answer:

> **Why did the model classify this object this way?**

Feature contributions can include velocity, miss distance, absolute
magnitude, diameter, and other model inputs.

### Put It in Perspective

A scale visualization compares an NEO's estimated size with familiar
reference objects, such as a human, aircraft, building, Moon, and Earth.

Example reference values include an illustrative human height of 1.7 m
and Earth's diameter of 12,742 km. Object values should come from the
underlying NASA-derived data and retain their uncertainty/range where
available.

### From Data to Signal

``` text
NASA NeoWs
    ↓
RAW OBSERVATIONS
    ↓
DATA CLEANING
    ↓
FEATURE ENGINEERING
    ↓
MACHINE LEARNING
    ↓
RISK CLASSIFICATION
    ↓
EXPLAINABILITY
```

This pipeline distinguishes original observations from processing,
derived features, model output, and interpretation.

## Data Sources

### NASA NeoWs

NASA's Near Earth Object Web Service provides information about
near-Earth asteroids and their close approaches.

Official source: https://api.nasa.gov/

### NASA/JPL Center for Near Earth Object Studies

CNEOS provides high-precision NEO orbit calculations, close-approach
information, and impact-risk assessment resources.

Official source: https://cneos.jpl.nasa.gov/

### JPL Horizons

JPL Horizons provides ephemerides and orbital information for
astronomical applications.

Official source: https://ssd.jpl.nasa.gov/horizons/

## Scientific Interpretation

NEO-SCOPE separates four layers of information:

1.  **NASA/JPL-derived information** --- retrieved from authoritative
    services.
2.  **Derived features** --- calculated or transformed by the project.
3.  **Machine-learning predictions** --- generated by the project's
    model.
4.  **Visual interpretation** --- presentation intended to help users
    understand the data.

### PHA Does Not Mean Guaranteed Impact

A Potentially Hazardous Asteroid (PHA) classification does not mean that
an object will collide with Earth.

PHA status is a scientific classification based on criteria involving
absolute magnitude and Earth Minimum Orbit Intersection Distance (MOID).
It should not be presented as a prediction that an impact will occur.

## Getting Started

### 1. Clone the repository

``` bash
git clone https://github.com/YOUR-USERNAME/neo-scope.git
cd neo-scope
```

### 2. Install dependencies

``` bash
npm install
```

### 3. Configure environment variables

Create a local environment file:

``` bash
cp .env.example .env.local
```

Add your NASA API key:

``` env
NASA_API_KEY=your_api_key_here
```

Never commit `.env.local` or any file containing private credentials.

Keep the API key server-side whenever possible. Do not expose it through
a public `NEXT_PUBLIC_*` variable unless there is a deliberate reason to
do so.

### 4. Start the development server

``` bash
npm run dev
```

Open:

``` text
http://localhost:3000
```

------------------------------------------------------------------------

## Machine Learning

The ML workflow is intended as an educational demonstration:

``` text
NASA observations
        ↓
Data cleaning
        ↓
Feature selection
        ↓
Feature engineering
        ↓
Train / validation split
        ↓
Model training
        ↓
Evaluation
        ↓
Prediction
        ↓
Explainability
```

Potential models include Random Forest and Gradient Boosting/XGBoost.

Useful evaluation metrics include:

-   Precision
-   Recall
-   F1-score
-   Accuracy
-   Confusion matrix
-   ROC-AUC where appropriate

Model performance should not be interpreted as a replacement for
NASA/JPL orbit determination or impact-monitoring systems.

## Data Pipeline Principles

-   Do not confuse visualization with prediction.
-   Do not confuse PHA status with impact probability.
-   Keep source data separate from model output.
-   Preserve scientific units.
-   Avoid presenting uncertain measurements as exact values.
-   Make data provenance visible wherever practical.

## Design Philosophy

NEO-SCOPE is designed as a scientific visualization experience rather
than a conventional analytics dashboard.

### Visual language

-   Deep-space black / navy
-   Ice-blue and cyan accents
-   Restrained violet highlights
-   Orange/red reserved for meaningful risk states
-   Selective liquid-glass interfaces
-   Cinematic Earth-from-space visual direction
-   Large editorial typography
-   Generous negative space
-   Scientific visualizations as the primary interface

### Typography

-   **Bricolage Grotesque** --- major headlines
-   **Instrument Sans** --- body and UI
-   **IBM Plex Mono** --- technical measurements only

The interface intentionally avoids excessive glowing borders, repetitive
card grids, and generic AI-dashboard aesthetics.

## Limitations

NEO-SCOPE is a student-built data science and visualization project.

It is **not**:

-   An official NASA application
-   An asteroid impact-warning system
-   A replacement for CNEOS
-   A professional orbital-determination system
-   A source of official impact probabilities
-   A substitute for scientific or governmental monitoring systems

NASA NeoWs is a REST API. Therefore, "live data" in NEO-SCOPE means data
retrieved or refreshed from the service, not continuous spacecraft
telemetry.

## Why This Project?

There is an enormous amount of astronomical data available through
public APIs, but raw data is rarely intuitive.

NEO-SCOPE explores:

> **Can real astronomical data be transformed into an interface that is
> both scientifically responsible and genuinely understandable?**

The project combines:

**Data Science + Machine Learning + Astronomy + Visualization + Web
Development**

to create an interactive way of understanding the objects moving through
our near-Earth environment.
